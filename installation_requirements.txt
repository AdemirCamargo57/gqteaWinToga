# ----------------------------------------------------------------------
# Runtime dependencies
# ----------------------------------------------------------------------

# GUI framework and its WinForms backend. Used by every tool window.
# Installs toga-core, pythonnet and pillow as dependencies, so none of
# those need to be listed here. Pillow is also imported directly: it draws
# the molecular design canvas (molecularCanvasRender.py) and the
# solvent-box builders' live construction view (boxConstructionView.py),
# and saves 3D-viewer images (matplotlib depends on it as well).
#
# Pinned to the 0.5 release line (0.5.3 is the verified version). The app
# patches toga-winforms 0.5's ScrollContainer (scrollPosition.py) so that
# scrolled tool pages - e.g. the 3D viewer's QTAIM tab - keep their scroll
# position when an option changes, instead of flashing back to the top.
# That patch copies 0.5's code and switches itself off on any other
# version, so the bug would silently return. Before raising this limit,
# re-check scrollPosition.py against the new Toga (see CLAUDE.md) and run
# tests/test_scrollPosition.py.
toga-winforms>=0.5.3,<0.6

# Numerical core: trajectory parsing, geometry, statistics. Imported by
# most analysis modules.
numpy

# Used by the autocorrelation FFT, the molecular pre-optimizer (L-BFGS-B),
# the solvent-box builders (random rotations) and their periodic
# pre-optimization (L-BFGS-B, periodic neighbour search via
# scipy.spatial.cKDTree), the ESP surface tool (Boys function via
# scipy.special, sparse mesh adjacency via scipy.sparse), and the molecular
# design canvas (bond detection on import and atom-number placement, both
# via scipy.spatial.cKDTree).
scipy

# All plotting, in both the main process (Agg) and the separate
# interactive plot-viewer process (TkAgg - see the system note below).
matplotlib

# Windowing and input for the 3D molecular viewer and the ESP surface
# viewer (espViewer.py, built on it). The wheel bundles glfw3.dll, so no
# separate GLFW install is needed for a pip install.
# (A packaged .exe build is different - see readme.md.)
glfw

# OpenGL bindings for the 3D molecular viewer and the ESP surface viewer.
# The Windows wheel bundles freeglut, which the viewers' on-canvas text
# labels need, so freeglut does not have to be installed separately either.
PyOpenGL

# Optional C speedups that PyOpenGL picks up automatically when present.
# Nothing imports it directly and the application runs correctly without
# it, only more slowly in the 3D viewer. It is the one entry here that
# can fail to install on a Python version with no matching wheel, since
# it would then need a C compiler; if that ever happens, comment it out
# rather than abandoning the install.
PyOpenGL-accelerate

# Renders cpx_input_description.pdf inside the cp.x input builder's help
# viewer. The import is guarded, so the rest of the application still
# runs without it - only in-app PDF help is lost.
PyMuPDF

# ----------------------------------------------------------------------
# Speed-ups: faster ESP surface and Fukui tools and solvent-box packing
#
# Installed by default, but optional at run time: every import of numba is
# guarded, so the application runs without it. If it cannot be installed
# (no wheel for a newer Python yet), comment the "numba" line out - the
# tools then run their numpy paths and give the same results.
#
# Compiles three kernel modules, each used automatically whenever
# "import numba" succeeds:
#   - densityNumba.py - electron densities on grids (ESP and Fukui tools)
#     and the Becke weights of the Hirshfeld charges. Agreement 1e-12
#     relative; about 4x faster (phenol, 222 000 points: 0.20 s instead of
#     0.83 s).
#   - espNumba.py - the electrostatic-potential sum of the ESP surface
#     tool. Agreement 1e-10 a.u., about 5x faster (benzene, 20 000 surface
#     points: 0.9 s instead of 4.7 s).
#   - solventPackingNumba.py - the clash test of the three solvation-box
#     builders ("Automatic" packing engine). Bit-identical boxes for the
#     same seed; 20-50x faster than the original insertion loop and 3-5x
#     faster than the numpy engine (e.g. a 26 x 26 x 52 A shared-wall
#     water/methanol box: 2.4 s instead of 114 s).
# The very first run spends a few seconds compiling; later runs load the
# compiled kernels from __pycache__. Installs llvmlite as a dependency.
# Leave it out of packaged .exe builds unless llvmlite is bundled too -
# the tools then simply run their numpy paths.
# ----------------------------------------------------------------------
numba

# ======================================================================
# System-level dependencies - NOT installable with pip
#
# These cannot be listed as packages above. Install them separately.
#
# 1. tkinter (Tcl/Tk)
#    A standard-library module that is not distributed on PyPI. The
#    interactive plot viewer (plotViewer.py) pins matplotlib's TkAgg
#    backend, which requires it.
#      Windows : included with the official python.org installer, as long
#                as the "tcl/tk and IDLE" component is selected. To repair
#                an existing install, re-run the installer, choose Modify
#                and enable that component.
#      Check   : python -c "import tkinter; print(tkinter.TkVersion)"
#    If it is missing, plots fail to open with no visible error rather
#    than raising - a blank result from the plot viewer is the symptom.
#
# 2. A graphical desktop session with working OpenGL drivers
#    The 3D molecular viewer creates a native OpenGL window through GLFW.
#    It cannot run over a plain SSH session, in a headless container, or
#    on a machine with no GPU driver installed. Remote Desktop sessions
#    may fall back to a software renderer and be slow.
#    Vendor GPU drivers (Intel, NVIDIA, AMD) supply the OpenGL runtime;
#    Windows' default Microsoft Basic Display Adapter driver does not.
#
# 3. Microsoft .NET runtime (Windows)
#    toga-winforms runs on WinForms through pythonnet. Windows 10 and 11
#    ship a suitable .NET Framework, so no action is normally needed;
#    a stripped-down or Server Core installation may not.
#
# 4. Gaussian (optional, for the ESP surface tool only)
#    The tool reads Gaussian formatted checkpoints (.fchk / .fch), made
#    from a .chk with Gaussian's formchk utility - on any machine where
#    Gaussian is installed. Gaussian is not needed to run the tool.
#    Its "Gaussian cubegen" ESP engine additionally needs cubegen.exe
#    (found via GAUSS_EXEDIR, PATH, C:\G09W or C:\G16W, or typed in the
#    tool); without it the built-in exact engine is used.
# ======================================================================
