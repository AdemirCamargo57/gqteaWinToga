# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**gqteaWinToga** (title: *gQTEA Molecular Analysis Toolkit*, current app version 1.0.0, set in the title label in `gqteaWinToga.py`; releases are tagged `vX.Y.Z`) is a Windows desktop GUI for preparing, converting, and analyzing molecular dynamics and electronic-structure simulation data (CPMD, Quantum ESPRESSO `cp.x`, ORCA, surface hopping, trajectory analysis). It is built with the [Toga](https://toga.readthedocs.io/) GUI framework on the WinForms backend.

The git repository lives in `venv/src/` (this directory), which is nested inside a Python `venv` created against Python 3.13. Run all commands from `venv/src/`.

## Running & Development

There is no build step or linter configured — this is a plain Python source tree launched directly.

```powershell
# From venv/src/ with the venv activated (..\Scripts\Activate.ps1)
python gqteaWinToga.py
```

There is a `pytest` suite under [tests/](tests/) (~2700 tests, one file per tool or shared module). Run it headless from `venv/src/`:

```powershell
python -m pytest tests/ -q
```

Four tests fail on `main` independently of any recent work — `test_meanResidenceTime.py::TestAdvancedOptionsExposed::test_every_run_parameter_is_supplied_by_the_ui` and three table-styling tests in `test_plotter.py`. Compare against that baseline rather than assuming a change of yours broke them.

Tests drive the analysis classes directly with stubbed Toga widgets/dialogs (no GUI is created); [tests/conftest.py](tests/conftest.py) puts the flat source dir on `sys.path` and pins the `Agg` matplotlib backend. It also has an **autouse fixture that re-pins `Agg` (`matplotlib.use("Agg", force=True)`) before every test**: any test that imports `plotViewer` triggers its module-level `matplotlib.use("TkAgg")`, which would otherwise switch the whole session to TkAgg and make a later PNG-rendering test try to start Tk in-process (order-dependent failures). Do not remove this fixture. New tests should follow the same pattern — instantiate the `*Analyser` logic class, not the `*UI` class.

Runtime dependencies (install into the venv if missing, or all at once with `python -m pip install -r installation_requirements.txt`, which documents what each one is for): `toga-winforms` (pinned `>=0.5.3,<0.6` there: [scrollPosition.py](scrollPosition.py) patches 0.5's ScrollContainer and turns itself off on other versions), `numpy`, `scipy`, `matplotlib`, `glfw`, `PyOpenGL`, `PyOpenGL-accelerate`, `PyMuPDF`. Pillow arrives with toga-winforms/matplotlib and is imported directly by [boxConstructionView.py](boxConstructionView.py) and the 3D viewer's image export — import it lazily. Optional: `numba` (0.68.0 verified with numpy 2.4.2), used by exactly four kernel modules — [espNumba.py](espNumba.py) (ESP tool, ~5×), [densityNumba.py](densityNumba.py) (AO values for every `electron_density` and `orbital_values` call, so the ESP, Fukui and NTO grids, plus Becke weights for Hirshfeld charges, ~4×; and, for the QTAIM tab, `cartesian_ao_derivatives` and the fused, AO-screened ρ/∇ρ/Hessian/G kernel behind `gaussianWavefunction.density_derivatives`, 8–65× over numpy and 1.4–3.6× over AO kernel + BLAS) [solventPackingNumba.py](solventPackingNumba.py) (solvation-box packing, 20–50× over the legacy loop) and [volumeNumba.py](volumeNumba.py) (the viewer Cube tab's marching-tetrahedra cell scan, ~4× on a 200³ grid, same triangle set; and `format_e13`, the `%13.5E` cube-value text every `cubeFile` writer uses, ~20×, **byte-identical** to Python's formatting — values within 1e-7 of a sixth-digit rounding tie, non-finite or with |exponent| > 300 are flagged and formatted by Python; `tests/test_cubeFile.py::adversarial_values` pins it). `NUMBA_KERNEL_MODULES` in [tests/test_solventPacking.py](tests/test_solventPacking.py) pins this list. **They must stay the only importers of numba and numba must stay optional**: each caller falls back to its numpy path, which gives the same numbers (bit-identical boxes for the packing). `installation_requirements.txt` must contain only installable requirement lines; every instructional line there is a `#` comment. Since 0.9.0 `numba` is an active line there (installed by default), but it is still **optional at run time** — keep every import guarded; the file says to comment the line out where no wheel exists. A graphical desktop session is required. The 3D molecular viewer needs `glfw3.dll` from `venv/Lib/site-packages/glfw/`.

Packaging to a Windows `.exe` is done manually with `auto-py-to-exe` (bundle the deps above; the GLFW DLL often must be added by hand). See `readme.md` for the full packaging notes.

## Architecture

**Flat module tree, one tool per file.** [gqteaWinToga.py](gqteaWinToga.py) is the only entry point. Its `gqteaWin(toga.App).startup()` imports one `*UI` class per tool and registers them as buttons across five `OptionContainer` tabs: **Geometry**, **Inputs** (`cpmd_tools`), **Structural**, **Thermo**, **Tools** (`general_tools`). Each button's `on_press` is the `*UI` class itself — clicking instantiates the class, which opens its own `toga.Window`.

**Standard per-tool pattern** (see [bond.py](bond.py) as the canonical example):
- A logic/analysis class (e.g. `BondAnalyser`) holding the numeric work and file I/O.
- A `*UI` subclass (e.g. `BondUI`) whose `__init__(self, *args)` calls `layout_main_window(widget)` to build the Toga window, then defines an `async workflow(self, widget)` that orchestrates: read/validate params → compute → write outputs → optionally show plots. `closeTopLevel` closes the window.
- Analysis classes multiply-inherit shared mixins rather than composing them.

**Shared mixins / modules** (inherited or imported by most tools):
- [analysisCommon.py](analysisCommon.py) — `GeometryAnalysisBase`, the shared machinery behind the three **single-item geometry tools** ([bond.py](bond.py), [bondAngle.py](bondAngle.py), [dihedralAngle.py](dihedralAngle.py)), which differ only in how many atoms they select and what scalar they form. Holds: `read_selected_atoms` (the one trajectory reader — parses **only** the selected atoms, treats a trailing blank line as clean EOF, and keeps the frames already read when it hits a truncated frame / unreadable header / atom-count mismatch); text-status reporting (`_set_status`, `render_summary`) and a `frames_counter` override, since **none of these three has a progress bar or frame-count label**; `_write_text` (guarded writes → dialog, never an unhandled raise); `minimum_image`/`min_image_limit`; `histogram_percent` (floor binning, out-of-range **counted, never clamped**); `basic_stats` (`ddof=1`); `smooth_series`; and `free_energy_from_histogram(jacobian=…)`. Subclass it **before** `FramesCounter` so its `frames_counter` wins, and set `tool_title`. Changing it changes all three tools — that is the point: it is what keeps their behaviour, feedback, output format and error handling identical.
- [framesCounter.py](framesCounter.py) — `FramesCounter` mixin: file-open dialogs, reads an `.xyz`/`TRAJEC.xyz`, sets `self.trajec`, `self.num_atoms`, `self.total_frame_number`, and `self.output_dir` (defaults to the trajectory's directory).
- [displayPlots.py](displayPlots.py) — `DisplayPlots` mixin: `save_plots(k, x, y, xlabel, ylabel, title, xlim=None, ylim=None, save_png=True)` records each curve (JSON-safe x/y data for the viewer, plus a static PNG unless `save_png=False`); the module-level `launch_plot_viewer(manifest_path)` is the **single** implementation of the viewer-spawn dispatch (source → `[python, plotViewer.py, manifest]`; `sys.frozen` → `[sys.executable, "--plot-viewer", manifest]`), used both by `display_plots()` and directly by [plotter.py](plotter.py)'s JSON plot type, which already has a manifest on disk. `display_plots()` launches [plotViewer.py](plotViewer.py) in a **separate process** to show interactive matplotlib windows (zoom/pan/save toolbar). This now works in **frozen/packaged builds too**: from source it spawns `[python, plotViewer.py, manifest]`; when `sys.frozen`, it re-launches the app's own exe as `[sys.executable, "--plot-viewer", manifest]`, which the [gqteaWinToga.py](gqteaWinToga.py) entry point dispatches to `plotViewer.main` *before* importing the Toga/OpenGL stack. `plotViewer.py` pins the `TkAgg` backend (must be bundled — see readme packaging notes); the static-PNG Toga-image-window path (`_display_static`) remains only as a fallback for when the viewer process cannot be spawned at all. The main process pins the `Agg` backend so it never conflicts with the viewer's GUI loop. `DisplayPlots.save_bar_comparison_plot(k, categories, groups, xlabel, ylabel, title, line=None, save_png=True)` is a fourth figure shape — a grouped bar chart with per-bar error bars and an optional line on a twin right-hand axis (used by [MolGeomComparator.py](MolGeomComparator.py) for its averages-and-percentage figure) — recorded in the manifest as `{"type": "bars", "categories": [...], "groups": [{"label", "values", "errors"}], "line": {"label", "values", "ylabel"}, "xlabel", "ylabel", "title"}`. The module-level `draw_bar_comparison(axes, figure_entry, font_style=None)` is the one renderer for this shape, imported by both `save_bar_comparison_plot` (drawing the optional static PNG) and `plotViewer.py`'s `"bars"` dispatch branch, so a figure looks identical from either process. A fifth shape, `{"type": "plane_map"}` (the QTAIM 2D map: `extent`, `grid` or null, `contours`, `lines` with a `kind` in `PLANE_MAP_LINE_STYLES`, `points` with a CP `type` in `PLANE_MAP_POINT_COLOURS`), is drawn by the module-level `draw_plane_map(axes, entry, font_style=None)`, the one renderer used by `plotViewer.py` and plotter's PNG fallback, imported in `plotViewer.py` on the same line as `draw_bar_comparison` (above the `TkAgg` pin); `save_plane_map_image(entry, path, dpi=200)` writes the same drawing to png/svg/pdf/tif through an off-screen Agg `Figure` (no pyplot state) for the QTAIM tab's *Export 2D image*; plotter's `_check_plane_map` validates it (messages name the figure) and `describe_json_figures` reports `N critical points, M lines`, so the replot tool reopens `<stem>_QTAIM_map.json`. A sixth shape, `{"type": "uv_vis"}` (the NTO tab's UV-Vis spectrum, see the NTO entry), is drawn by `draw_uv_vis`, imported on the same `plotViewer.py` line. A seventh, `{"type": "heat_map"}` (`matrix` rows, `row_labels`, `col_labels`, `vmin`/`vmax` or null, `colorbar`; the Excitation tab's composition and charge-transfer matrices), is drawn by `draw_heat_map` (same import line); plotter's `_check_heat_map` validates it and `describe_json_figures` says `R x C heat map`. Manifest entries written before this shape existed carry no `"type"` key at all and are unaffected — the plain single-curve figure stays the default when `"type"` is absent. In `plotViewer.py`, `from displayPlots import draw_bar_comparison` must stay **above** the `matplotlib.use("TkAgg")` line: `displayPlots.py` pins `Agg` at import time, so importing it after the `TkAgg` pin would silently re-pin `Agg` and the interactive viewer would open no window at all. Because the viewer imports this module, **`displayPlots.py` must not import Toga at module level**: `import toga` / `from toga.style import Pack` are deferred *inside* `_display_static`, the only method that uses them. The [gqteaWinToga.py](gqteaWinToga.py) entry point dispatches `--plot-viewer` **before** loading the Toga/OpenGL stack precisely so a viewer child never drags the GUI in, and a module-level Toga import here would quietly defeat that for **all** tools — a frozen build trimmed of Toga on the viewer path would then lose interactive figures everywhere, with the same silent no-window symptom as a missing `TkAgg`. Two subprocess tests in [tests/test_displayPlots.py](tests/test_displayPlots.py) assert `toga` stays out of `sys.modules` after importing `displayPlots` and after importing `plotViewer`. Shared by all analysis tools, so plotting changes here are global.
- [plotter.py](plotter.py) — `PlotterBase`/`PlotterUI`, standalone energy-plot tool that parses both CPMD and gqteaMD energy files. A third **Plot type**, `JSON_PLOT_TYPE`, replots an existing **plotViewer manifest** (the JSON any tool writes via `DisplayPlots.save_plots`), so figures can be reopened without recomputing. `validate_plot_manifest` / `load_json_plot_file` are pure classmethods (hence unit-tested in [tests/test_plotter.py](tests/test_plotter.py)) that reject a bad file with a message naming the offending figure — e.g. `Figure 3: 'x' and 'y' must have the same length (5 vs 4).`; `describe_json_figures` renders the loaded-figure summary. All three JSON entry points understand the **`{"type": "bars"}`** shape as well as `series` and `x`/`y`: `validate_plot_manifest` checks a bars entry's `categories` is non-empty and that every group's `values` (and its `errors`, and the optional `line.values`) match that length, naming the offending figure as the other branches do; `describe_json_figures` reports it as `N groups, M categories`; and `json_plot_static` renders it through `draw_bar_comparison` rather than falling through to `plt.plot`. This matters because [MolGeomComparator.py](MolGeomComparator.py) leaves its bars manifest in the user's output folder — without these branches the project's own replot tool would reject a file the project itself wrote. `on_plot_type_change` is a **three-way** switch: `is_cpmd = not is_gqtea and not is_json` gates the six CPMD switches, the time step and the unit selector, so JSON mode disables every other plot-specific control and clears `json_figures`. Plotting hands the user's file straight to `launch_plot_viewer` (see below) and only falls back to `json_plot_static` (PNG + `show_plot`) if the viewer cannot be spawned. A fourth **Plot type**, `TABLE_PLOT_TYPE` ("Multi-column data file"), plots column 1 as x against every other column: `parse_table_text` / `load_table_file` are pure classmethods (tested in [tests/test_plotter.py](tests/test_plotter.py)) that skip blank lines, `TABLE_COMMENT_PREFIXES` lines and trailing `# ...`, split on comma → tab → whitespace, and take the **last non-numeric, non-comment line before the first data row** as the column-name header (its names become legend labels; a commented header is ignored, per the spec). After data starts, a non-numeric, ragged or non-finite line is a `ValueError` naming the line — text is never parsed as data. `table_to_figure` turns the table into one `series` manifest figure, written to the **system temp dir** (never next to the data) and handed to `launch_plot_viewer`; the PNG fallback is the shared `render_figures_static`, which `json_plot_static` now delegates to. `on_plot_type_change` is therefore a four-way switch (`is_cpmd = not gqtea/json/table`) and also clears `table_data`, the two axis-label inputs and the style rows. **Window height:** it also shows *only* the active type's sections (`cpmd_switch_box`/`time_step_box`/`units_box`, `gqtea_column_box`, `table_options_box`) via `show_sections` — stacking all of them, merely disabled, pushed the window past a laptop screen. Each section sits in its own empty slot box (`_add_section`, `self._section_slots`) and is **removed from / re-added to its slot**, because Toga 0.5's Pack layout **ignores `display="none"`** (a hidden widget keeps its full height). Two ordering rules keep the window at its 620 px: `show_sections` removes hidden sections **before** adding shown ones (otherwise both types coexist for a moment and the window grows, and Toga never shrinks it back), and `layout_main_window` calls `on_plot_type_change` **before** setting `main_window.content` for the same reason. The gqteaMD y-column switches and the table style rows each live in a fixed-height (110 px) `ScrollContainer`, so a wide file cannot grow the window either. Table customisation: `table_to_figure(table, title, xlabel, ylabel, styles, include)` — blank labels fall back to the header's first name / `"Value"`; `styles` is one `TABLE_LINE_STYLES` key per y column (label → `(linestyle, marker)`) and `include` one bool per y column (default all; all-False is a `ValueError`). Both are indexed **by column, not by plotted curve**, so a style stays with its column whichever columns are left out. `update_table_style_controls(labels)` rebuilds one row per y column (inside a fixed-height `ScrollContainer`) on every load — a `toga.Switch` named after the column (on by default; its `on_change` greys out that row's style) plus a `toga.Selection` — read back in column order by `selected_table_columns()` / `selected_table_styles()`. The styles travel as **optional `linestyle`/`marker` keys on a `series` curve**; `validate_plot_manifest` restricts them to `SERIES_LINESTYLES`/`SERIES_MARKERS` (an unknown value would crash the viewer), and both renderers apply them through the one helper `displayPlots.series_style_kwargs`, so a curve without them draws exactly as before. A fifth **Plot type**, `BAR_PLOT_TYPE` ("Bar chart data file"), draws grouped bars and reuses all of the table machinery rather than duplicating it: `parse_table_text(text, categorical_x=True)` / `load_table_file(..., categorical_x=True)` keep column 1 as the **text written in the file** (a symbol like `C1`, or a number like `2.50`, never converted) and require only columns 2+ to be numeric, so a data row is "label + numbers" (the result carries `categorical_x`). The flag defaults to `False`, which leaves the line-table parser byte-for-byte unchanged. `bar_table_to_figure(table, title, xlabel, ylabel, include)` emits a `{"type": "bars"}` manifest figure, so it is drawn by the existing `displayPlots.draw_bar_comparison` in both the viewer and the PNG fallback. No new renderer exists, and none should be added. The bar type shares `table_options_box` (the axis-label fields + per-column rows). `update_table_style_controls(labels, with_styles=False)` builds **switch-only** rows (bars have no line style), `table_styles_label.text` toggles between `TABLE_COLUMNS_HEADING`/`BAR_COLUMNS_HEADING`, and `show_table_figure` is the one temp-dir-manifest → `launch_plot_viewer` → static-fallback path for both table types. Known parsing edge: a pre-header title whose words after the first are all numeric (`Step 5`) reads as a data row. Fixture: [tests/data/plotter/fukui_condensed_phenol.txt](tests/data/plotter/fukui_condensed_phenol.txt), a Fukui-tool condensed-index table.
- [help.py](help.py) — `AtomicData` (element `atomic_masses`, `atomic_numbers`, `covalent_radii`, `max_valence`, `max_bond_order`, `valence_electrons`, etc.), `Fonts`, and `HelpGqteaWin` (long help strings like `help_bond_analysis` shown in each tool's `MultilineTextInput`). This is the shared reference-data + help-text hub. The four chemistry tables after `lang` back the molecular design tool: `covalent_radii` (Cordero 2008) gives reference bond lengths and decides whether an element can be placed at all; `max_valence` is the *typical* valence a design warns about exceeding, never blocks; `max_bond_order` caps the click-to-raise bond-order cycle per element (H/halogens 1, O/S 2, absent means 3); `valence_electrons` exists so the pre-optimizer can count lone pairs for a VSEPR steric number — **it is what makes water bend instead of coming out linear**, so do not replace it with a bond count.

- [scrollPosition.py](scrollPosition.py) — `keep_scroll_position_on_relayout()`, applied once in `gqteaWin.startup` (and again, idempotently, in `MolecularViewerUI.layout_main_window`). toga-winforms 0.5's `ScrollContainer.refreshed` ends with `AutoScroll = False; AutoScroll = True` (a DPI-change workaround), and `refreshed` runs on **every** re-layout of a scrolled page (any `Label.text`, `Selection.items`, `TextInput.value` write inside it), so a scrolled tab jumped to the top and flashed whenever an option was chosen far down it (reported on the viewer's QTAIM Canvas section). Restoring the position after the toggle does **not** work — the panel has no scroll range at that moment and WinForms clamps to 0 — and the toggle itself moves the pixels on screen, so the patch replaces `refreshed` with the same layout pass **minus the toggle**; Toga's original (toggle included, then `PerformLayout` + restore) still runs when the container's DPI scale changed since its last layout. It mirrors 0.5's code, so it installs only for `toga_winforms.__version__` 0.5.x (otherwise returns False and changes nothing — re-check it when upgrading Toga). Toga is imported inside the function (subprocess test). Covered by [tests/test_scrollPosition.py](tests/test_scrollPosition.py) with fake native panels; the live behaviour was checked in the real viewer window (QTAIM tab scrolled to 597 px stays there through style changes and atom-size steps).

**Conventions observed across tools:**
- Async Toga event handlers throughout; user errors surface via `toga.InfoDialog` (often a `warning_function` helper) rather than exceptions.
- `.xyz` format is parsed manually: line 1 = atom count, line 2 = comment, then `num_atoms` lines of `element x y z`. Atom labels in the UI are **1-based**.
- Outputs (`.dat`, `.csv`, summary `.txt`, plots) are written next to the input file in `self.output_dir`. Time is derived from the atomic time unit constant `atufs = 0.02418884326505` fs.
- Files may contain large commented-out "previous version" blocks kept for reference (e.g. the bottom half of `bond.py`); the active code is the uncommented top.
- Two distinct trajectory formats are in play: CPMD **`TRAJEC.xyz`** (standard `.xyz`, positions in Å) and CPMD **`TRAJECTORY`** (no per-frame header; each line is `step x y z vx vy vz` in atomic units, positions *and* velocities). [autocorrelationFunction.py](autocorrelationFunction.py) reads the latter and needs `GEOMETRY.xyz` loaded first for the atom count. Note the `TRAJECTORY` file can contain CPMD **restart markers** (`<<<<<<  NEW DATA  >>>>>>`) and blank lines mid-file when a run is continued; any code reading it must skip non-data lines to keep atom framing aligned (see `_next_atom_tokens`).

## Interactive figures without PNG clutter (reusable recipe)

The pattern first applied in [radialDistribution.py](radialDistribution.py): show plots **only** through the interactive viewer (zoom/pan/save toolbar) — working in both source and packaged/frozen builds — and stop leaving static PNG files next to the user's data. The plumbing is already global in [displayPlots.py](displayPlots.py), [plotViewer.py](plotViewer.py), and the [gqteaWinToga.py](gqteaWinToga.py) entry point, so **applying it to another tool is a one-line change per plot call**:

1. In the tool, pass `save_png=False` to every `save_plots(...)` call (and keep the single `self.display_plots()` after them). That is the whole change — the tool already benefits from the frozen-build viewer via the shared mixin.
2. No change needed to `display_plots()`: from source it spawns `[python, plotViewer.py, manifest]`; when `sys.frozen` it re-launches the app's own exe as `[sys.executable, "--plot-viewer", manifest]`. The [gqteaWinToga.py](gqteaWinToga.py) entry point intercepts `--plot-viewer <manifest>` **before** importing the Toga/OpenGL stack and dispatches to `plotViewer.main`.
3. Packaging requirement (once, global): the frozen build must bundle `tkinter` / the **`TkAgg`** backend that `plotViewer.py` pins, or the interactive window silently fails to open (see readme packaging notes). If a build shows *no* window rather than a PNG, `TkAgg` is missing from the bundle.
4. `save_multiseries_plot` (overlay figures) takes the same `save_png` flag — pass `save_png=False` there too for tools that overlay curves (e.g. total + partial VDOS in `autocorrelationFunction.py`).
5. `_display_static` (static PNG in Toga image windows) remains only as a fallback for when the viewer subprocess cannot be spawned at all; with `save_png=False` there is no PNG to fall back to, which is the intended trade-off.
6. Tests: assert `glob("*.png") == []` in the output dir after the workflow while the `.dat`/`.csv` output is still written, and (for the shared behavior) that `display_plots()` spawns the viewer under both `sys.frozen = False` and `True`. See [tests/test_radialDistribution.py](tests/test_radialDistribution.py) for the reference tests.

## Tool-specific notes

- **[autocorrelationFunction.py](autocorrelationFunction.py)** — VAF/PAF are averaged over all overlapping time origins, include lag 0, and are normalized to `C(0)=1`; positions are mean-subtracted per atom before the PAF. The correlation uses an **FFT (Wiener–Khinchin) estimator** (`_fft_autocorrelation`, via `scipy.fft` with `workers=-1`): O(N log N) instead of the old O(N·max_lag) lag loop, verified identical to the direct method to ~1e-15 (~22× faster on the compute). `_is_data_line` is a cheap `len(tokens) >= 7` test (restart markers have 4 tokens) — do not re-add float-parsing there; the values are parsed once when stored. Note: a `np.fromstring` bulk loader was tried and rejected (10× slower, ~1 GB) — keep the line-by-line loader. On `TRAJECTORY` load, blank frame fields are auto-filled for the whole trajectory (`_apply_frame_defaults`): start=1, stop=last frame, and *Number of frames for each ACF* = `_default_num_frame_acf()` ≈ 10% of frames capped at 2000. The power spectrum (`calculate_psd`) is the Wiener–Khinchin route on the VAF: mean-removal → mirror about t=0 → window (Welch/Hann/None) → zero-pad → `rfft` → `|·|²`, one-sided, peak-normalized, with a physical frequency axis (cm⁻¹/THz/Hz from the time-step × sampling-interval spacing). Mass-weighting (masses from [help.py](help.py) `AtomicData`) computes a separate mass-weighted VACF (`self.vaf_mw`) in the same correlation loop and emits `VDOS.dat`; the plain spectrum emits `PSD.dat`. PSD UI controls: `switch_mass_weight`, `selection_window`, `textInput_zero_pad`, `selection_freq_unit`, `textInput_partial`. **Partial VDOS** (`textInput_partial`, parsed by `_parse_partial_groups`): `;`-separated groups of element symbols and/or 1-based atom indices/ranges; each group's atoms give a partial VACF (`self.partial_vacfs`) whose spectrum is overlaid on the total (each normalized to its own max) and saved as `PSD_<group>.dat`/`VDOS_<group>.dat` — used for vibrational-mode assignment. Overlays use `DisplayPlots.save_multiseries_plot` + the `series` manifest format in [plotViewer.py](plotViewer.py). All plot calls here pass `save_png=False` (see the *Interactive figures without PNG clutter* recipe), so figures are shown only through the interactive viewer and **no static PNG files are written** next to the trajectory.
- **[radialDistribution.py](radialDistribution.py)** — g(r) around a single **shell-center** atom (`shell_center`, 1-based) to all atoms of a target symbol, from `TRAJEC.xyz`. Periodic boundaries use the vectorized **minimum-image convention** (`delta -= box * round(delta/box)`), which is exact only for `radius ≤ min(a,b,c)/2` — this bound is enforced in `read_params` (which returns `bool`; `workflow` aborts if it fails). Because this same `min(a,b,c)/2` is the **default applied when the radius field is left blank**, `read_params` reads and validates the cell lattices **first**, then reads the radius via the `read_optional_float` helper (blank → default, otherwise parsed/validated like `read_input` but not required). Coordinates need **not** be wrapped into the box: min-image tolerates unwrapped input, verified by a box-shift-invariance test. - **[MolGeomComparator.py](MolGeomComparator.py)** — compares the geometric parameters of the **same molecule** across two simulations (the case it was built for: isolated vs. solvated, solvent already stripped). Consumes the combined files written by the three all-* tools; `MolGeomCalculator` + `MolGeomComparatorUI`, newer `margin=` style — the UI now mixes in `DisplayPlots` (see below) for the comparison figure, so it is no longer plot-free, but the calculator itself still has no mixins. The three input formats differ only in atom count and value-column name, so a **declarative `ParameterKind` table** (`BOND_KIND`/`ANGLE_KIND`/`DIHEDRAL_KIND`) drives one reader: the type comes from the `# gQTEA All ... Analysis` title line and **columns are located by name** from the file's own `# row` header, never by position. **The whole problem is index remapping**: a solvated run analysed with `solute_atom_indices` prints the atoms' *global* box indices (the reference molecule's oxygens at 295-297) for atoms the isolated run calls 29-31, so every row is canonicalised to a **solute-local** index — the atom's rank in the sorted `# solute_atom_indices` list — which makes any pair of scopes comparable (all↔all, all↔solute, solute↔solute). The remap is **verified, not assumed**: `_validate_same_molecule` aborts naming the offending atom if the two files disagree on any shared atom's element or on the molecule size, because a wrong mapping yields plausible-looking nonsense. Matching keys on `canonical_identity`, which folds the orderings that mean the same parameter (bond undirected; angle keeps its vertex, arms sorted; dihedral equal to its own reversal) — `canonical_elements` permutes the element tuple the same way, so reported atoms and elements stay aligned. **Dihedral differences go through `angular_difference`** (wrap into (-180, 180]) or a +179°→-179° shift reads as -358°. **Two independent, signed relative-difference formulas** are computed for every matched parameter regardless of which switches are on — `percent_difference` = `100*(avg_2-avg_1)/mean(avg_1,avg_2)` and `percent_error` = `100*(avg_2-avg_1)/avg_1`, both file 2 minus file 1 — because the `switch_percent_difference`/`switch_percent_error` UI modes gate only what reaches the output file and the plot, never the computation itself. Each `ParameterKind` carries its own `percent_floor` (`1e-6` Å for a bond, `1.0` degree for an angle or a dihedral, since a bond length is never near zero but a dihedral genuinely can be); `_as_percent` writes `nan` when `abs(denominator) < percent_floor` and the run counts these into `self.percent_undefined`. For a periodic kind the symmetric percentage's denominator is not `mean(avg_1, avg_2)` but `circular_mean` of the two angles, because the arithmetic mean of +179° and -179° is 0°, which would divide by (almost) zero for two nearly identical dihedrals. Selected percent columns (`percent_column_name`) are **appended** after `difference_<second>_minus_<first>` in `matched_columns`, never inserted earlier, so a reader that indexes the columns above by position keeps working; with neither `percent_modes` switch on, `_write_percent_header` writes nothing and the file is byte-for-byte what it was before relative differences existed — no selected mode on its own reproduces that original file, since each one adds at least its percent column and header block. `global_metrics()` adds a `# mae_<unit>`/`# rmsd_<unit>` pair (native unit, every matched parameter) plus a `# mae_percent_*`/`# rmsd_percent_*` pair per selected mode (over `abs()` of that percentage, skipping undefined rows) to the header, alongside `# global_metric_category`/`# global_metric_n`; the same numbers are echoed in `summary_text()`, whose *Largest shifts* table also gains one signed percent column per selected mode (`_format_shift_percent`, canonical order, `nan` rendered as a right-justified token so the fixed-width alignment survives). A mode whose rows are *all* undefined has no `mae_<mode>` key at all — `global_metrics()` omits the pair rather than storing `nan` — so `summary_text` guards with `if ("mae_" + mode) not in metrics: continue` before indexing it. The occurrence filter is applied **before** matching, deliberately: a sub-cutoff artifact (the H-H pairs at 1.67-1.70 Å) surviving in one file only would otherwise be reported as a parameter the other simulation lacks. Output is one self-describing file (`geometry_comparison_<type>.txt`) with a metadata header — including `# file_N_local_to_global` for the renumbered atoms only, so rows stay narrow — and **three `# section` blocks** (`matched`, `only_in_file_1`, `only_in_file_2`), each with its own `# row` line; matched column names carry the user's labels (`average_isolated`, `difference_solvated_minus_isolated`) and `source_row_1/2` trace each row back. Every failure is a `ValueError` with a specific message, caught by the UI into `toga.InfoDialog` — nothing raises out of the async handler. When **Open the comparison figure after comparing** (`switch_show_plot`) is on, `_show_comparison_plot` ranks parameters by `largest_shifts`, takes the top `textInput_plot_count` (`parse_optional_positive_int`, blank → 25), and calls `save_bar_comparison_plot` (see the `displayPlots.py` bullet below) with `save_png=False` per the project's interactive-figures recipe, so no image file lands next to the parameter files; with both percent switches on, the plotted line is always `PERCENT_MODES[0]` (the symmetric difference), and `PLOT_LABELS`/`PLOT_AXIS_LABELS` name it in the legend and the right-hand axis. Help text is `HelpGqteaWin.help_mol_geom_comparator`. Covered by [tests/test_MolGeomComparator.py](tests/test_MolGeomComparator.py) (parser, malformed-file rejection matrix, remap, canonical identity, wrap, filter, output format, and the UI plumbing headless via `__new__` + stub widgets).
- **[meanResidenceTime.py](meanResidenceTime.py)** — MRT of an atom/group around a reference centre, from a multi-frame `.xyz`. Self-contained (`MeanResidenceTimeCalculator` + `MeanResidenceTimeUI`, no shared mixins). Occupancy `h[obj, frame]` = "within `cutoff` of the reference"; `apply_tolerance_to_occupancy` implements the IMM `t*` gap-bridging (it deliberately does **not** bridge leading/trailing gaps). **Two continuous time constants are reported and they are different quantities** — `mean_residence_time` = ⟨T⟩, the mean duration of complete events, and `imm_survival_time` = ∫S(t)dt for the **origin-averaged** survival of Impey–Madden–McDonald, which is mathematically the mean *residual* time ⟨T²⟩/(2⟨T⟩) and equals ⟨T⟩ only for exponential kinetics. Before this was fixed the module reported ⟨T⟩ **twice** (as `direct_continuous_mrt` and `continuous_mrt`, which differ by exactly one `dt` since ∫P(T≥t)dt = E[T]); do not reintroduce that pairing. `compute_origin_averaged_survival` uses the closed form `S(l) = Σ max(0, nᵢ−l) / Σ nᵢ` over run lengths — exactly equivalent to scanning every time origin (the tests check it against a brute-force origin scan) but O(events) per lag. - **[meanResidenceTime_classical.py](meanResidenceTime_classical.py)** — the "Mean Residence Time Classical" button (documented in USER_MANUAL as *Legacy Mean Residence Time*; help `help_mrt`). The time step has an **a.u./fs** selector (`TIME_STEP_UNITS`, a.u. first: CPMD) and the **tolerance** a **frames/fs** selector (`TOLERANCE_UNITS`; the label follows it via `on_tolerance_unit_change`; default `0`, blank = 0). The module-level pure functions are the single definition: `frame_interval_fs(step, unit, sampling)` = step (fs) × sampling — for a.u. it is bit-identical to the old `atufs*step*sampling` time axis — and `tolerance_in_frames(value, unit, dt)`, which **rounds fs down** (`floor(t/dt + FRAME_ROUNDING_SLACK)`): an n-frame excursion lasts n·dt and is tolerated iff n·dt ≤ t, so n frames and n·dt fs give byte-identical outputs (test), and the slack absorbs `0.3/0.1 = 2.999…`. - **[molecularSketch.py](molecularSketch.py) / [periodicTable.py](periodicTable.py) / [molecularDesign.py](molecularDesign.py) / [molecularPreOptimizer.py](molecularPreOptimizer.py)** — the **Design** tab of [molecularViewer.py](molecularViewer.py): draw a molecule with the mouse across two windows, pre-optimize it, send it to the 3D viewer. A strictly one-way dependency chain `molecularViewer → molecularDesign → {periodicTable, molecularFileFormats, molecularHydrogens, molecularPreOptimizer → molecularGeometry, molecularSketch, molecularCamera} → help`, so **only `molecularDesign.py` and `periodicTable.py` import Toga** and the other three are tested with no stubs at all (a subprocess test in each asserts `toga` stays out of `sys.modules`).
  - **The canvas is 3D.** Every `SketchAtom` has a depth `z`; the design canvas projects the drawing through a `ViewCamera` ([molecularCamera.py](molecularCamera.py)) and can be rotated (left-drag on empty space or a bond), panned (right-drag) and zoomed (mouse wheel about the pointer, or the buttons about the centre) while building -- the 3D viewer's mouse mapping. **Coordinates stay in sketch units** — canvas pixels at the default view (x right, y down) plus `z` *away* from the viewer, which keeps the frame right-handed — rather than switching the model to Å, so a fresh canvas behaves exactly like the old flat one and `molecularPreOptimizer` remains the only module that knows the pixel/Å scale. The camera is orthographic, `screen = zoom·(R(p − pivot))[:2] + anchor`, `depth = (R(p − pivot))[2]`, and its **default is the identity**, which is why the pre-3D tests (written in raw pixels) still pass unchanged. `set_pivot` moves the anchor to compensate, so rotating about the molecule's centre never makes the picture jump; `rotate_by_drag` re-orthonormalises via SVD so thousands of drags cannot shear. **The view is never an edit**: it pushes no undo entry, does not bump `_edit_generation` and leaves `last_result` valid.
  - **Three windows, one controller.** The Design tab is only a **launcher** (two buttons, a selected-element label, a status line, the help). The drawing happens in two separate `toga.Window`s: `PeriodicTableWindow` and `DesignCanvasWindow`. `MolecularDesignController` owns *all* state — sketch, selected element, undo stack, last result — and **touches no widget**; the windows are disposable views registered with `register_view`/`unregister_view`. **This split is forced, not stylistic:** Toga documents that *a closed window cannot be reused*, so reopening one means constructing a new object — if the sketch lived in the canvas window, closing it would destroy the user's drawing. It is also what makes cross-window element selection work: the two windows never reference each other, they only talk to the controller, which broadcasts `on_element_changed` / `on_sketch_changed` / `on_status_changed` to every live view. `register_view` replays the current selection, status and drawing immediately, so a reopened window never shows stale state. `_on_close` on each window unregisters it and nulls the controller's reference (Toga's `close()` does **not** fire `on_close`, so `close()` does it explicitly); `close_windows()` is called from the viewer's own `on_close` so design windows never outlive their parent.
  - **[molecularSketch.py](molecularSketch.py)** — `MoleculeSketch`, the single source of truth for what was drawn: `SketchAtom`/`SketchBond` in **sketch coordinates** (canvas pixels plus depth `z`, default 0), never Ångström. `positions()` / `update_positions(array)` read and write all atoms as an `(N, 3)` array in `ordered_atom_ids()` order — the write-back path for an optimized geometry, which refuses a wrong shape or a non-finite value before moving anything; `copy()` is an independent duplicate. `atom_at` / `bond_at` take an optional `screen` mapping (atom id → projected `(sx, sy, depth)`); without it the atoms' own x/y are the screen positions. `atom_at` ranks hits by `(outside ATOM_DISC_RADIUS, depth, distance)`, so after a rotation the atom the user can **see** (the one in front) wins. **Atoms are addressed by a stable integer id, never by list position** — deleting an atom would otherwise renumber every bond, the exact off-by-one class this project has been bitten by before; ids are never reused and `ordered_atom_ids()`/`bond_index_pairs()` are the *only* places an id becomes a 0-based index. **`SketchBond.order` is a `float`**: 1, 2, 3 and `RESONANCE_ORDER = 1.5`. A delocalized bond genuinely *is* order 1.5, so storing it as a number rather than an `is_aromatic` flag means valence sums, reference bond lengths and the planarity torsion all keep working arithmetically with **no second code path** — and `bond.order == 2` still reads true, so the change cost the existing tests nothing. `bond_order_cycle(cap)` is the data-driven click cycle: cap 3 → `(1, 2, 3, 1.5)`, cap 2 → `(1, 2, 1.5)`, cap 1 → `(1,)`, so **resonance is offered exactly where a double bond is possible and never on an O–H**; `cycle_bond_order` steps round it and wraps, so one gesture both raises and lowers and no state is unreachable (an order outside the cycle falls back to single rather than stranding the bond). `validate()` returns `(errors, warnings)` and is the whole "warn, don't block" policy: an empty sketch, a stray unbonded atom beside a molecule, or an element with no covalent radius are **errors** that stop optimization; an unusual valence, **an isolated resonance bond** (`_has_resonance_neighbour` — one shared end is enough, so carboxylates and amides pass while a lone delocalized bond is flagged) and several disconnected fragments are **warnings** that do not. Nothing is ever auto-added while drawing — hydrogens come only from the explicit **Add hydrogens** button (see below). The sketch also stores **frozen parameters** (`SketchConstraint(kind, atom_ids, value)`, value in Å/degrees, never pixels; `set_constraint` replaces one on the same atoms read forwards or backwards); `remove_atom` drops every constraint naming the atom, and **`snapshot()` is now a 4-tuple** (atoms, bonds, next id, constraints) so Undo restores constraints with their atoms — `restore` still accepts the old 3-tuple. `add_structure` (beside the drawing) and `replace_contents` share `_checked_structure`, all-or-nothing.
  - **[molecularPreOptimizer.py](molecularPreOptimizer.py)** — `build_3d_seed` → `ForceField` → `optimize_sketch`, pure numpy/scipy, **no new dependencies** (RDKit/OpenBabel were considered and rejected: the PyInstaller bundle already fights over `glfw3.dll` and `TkAgg`). The seed converts with `sketch_to_angstrom` = `(x, −y, −z) / PIXELS_PER_ANGSTROM` (40) — a **180° rotation about x, not a y flip**: flipping y alone is a reflection and would hand back the *mirror image* of a chiral 3D structure (a test pins handedness through a full optimize-and-write-back of CHFClBr). Only a drawing flat to within `SEED_PLANARITY_TOLERANCE` (0.05 Å) is lifted off **its own best-fit plane** (`_plane_normal`, sign-fixed for determinism; for a z = 0 drawing this is exactly the old z jitter, so existing results are unchanged) with a **fixed-seed** RNG — deterministic, because a perfectly planar start leaves angle and torsion gradients exactly zero and the minimizer would never leave the plane; an already-3D sketch is used exactly as drawn. After minimizing, `align_onto` (Kabsch, proper rotations only) fits the result onto the un-jittered drawing so the canvas shows the molecule relaxing **in place**, and `OptimizationResult.sketch_positions` carries it back in sketch units at the drawing's centroid (`coordinates` is the same aligned structure in Å, centred). `reference_bond_length(el_i, el_j, order)` is the single source of the bond-stretch reference length, reused by the canvas for grown atoms. Four terms, all with **analytic gradients**: bond stretch about `(r_i + r_j) × BOND_ORDER_LENGTH_SCALE[order]`, calibrated against experiment (single 1.00 → 1.52 Å, **resonance 0.92 → 1.40 Å**, double 0.88 → 1.34 Å, triple 0.80 → 1.22 Å for C–C); **angle bend harmonic in `cos θ`, not `θ`** — that removes the `1/sin θ` singularity a hand-drawn CO₂ hits on its way to 180°, and a `θ₀` of 180° gets the separate `(1 + cos θ)` form so its minimum stays first-order steep; a twofold torsion on bonds of **order ≥ `RESONANCE_ORDER`**, so an aromatic ring is flattened by all six of its bonds rather than being free to pucker; and a repulsive-only `(σ/r)¹²` between atoms **at least four bonds apart**. θ₀ comes from `ideal_angle_degrees`, a VSEPR steric number = σ-bonds + lone pairs, whose floor division handles fractional sums with no special case (aromatic C → trigonal; pyridine N, 1.5+1.5 with one lone pair → trigonal, not linear). The **finite-difference gradient test is load-bearing** — it caught a wrong sign convention in the torsion's two central-atom terms (`d_phi_d_i`/`d_phi_d_j`), which had also been making the minimizer thrash (the suite ran 6× slower); those coefficients are sign-convention sensitive, so pin them with that test rather than trusting a remembered formula. `optimize_sketch` raises `ValueError` on validation errors and **never** raises for non-convergence: that is `success=False` plus the minimizer's message, with the partially relaxed coordinates still returned. Documented limits: relative energy units, main-group/organic tuning, steric number 6 comes out distorted.

A view change: no undo, `last_result` kept. Live-checked: one notch gives exactly 1.1 (no double zoom). Note when testing drags live: WinForms takes a `MouseMove`'s button from the hardware, so posted `WM_MOUSEMOVE` messages arrive with no button; drive Toga's `impl.winforms_mouse_down/move/up` with real `MouseEventArgs` instead. `_push_undo` **clears `last_result`**, which is what guarantees the structure sent to the viewer always matches the current drawing; it and `undo` also bump `_edit_generation`. **Write-back:** `apply_optimization_result` pushes undo, `update_positions(result.sketch_positions)` (only when the shape matches the current atom count), and sets `last_result` **after** that push, since the push clears it — so Undo restores the hand-drawn layout. `pre_optimize` optimizes `self.sketch.copy()` (the minimizer runs in `asyncio.to_thread` while the canvas stays live) and discards the result if `_edit_generation` moved meanwhile. Rendering: `drawing_order()` is the testable painter's list — `(kind, item, fade)` back to front, bonds at their ends' mean depth and, at equal depth, before atoms (so a flat drawing paints exactly as before); `fade` 0→1 drives `DEPTH_SHRINK`/`DEPTH_FADE` via the pure `blend_color`. Bond lines are **trimmed to the disc edges** of their atoms: a bond shares an endpoint with each atom, so no paint order can stop a centre-to-centre line crossing the disc it is painted after (seen in a live smoke run). A resonance bond is drawn as one solid line plus a parallel **dashed** line (`_stroke_line(..., dashed=True)`), distinct from the 1/2/3 solid lines of the other types. `transfer_to_viewer()` is a **sync, dialog-free seam** returning `(ok, message)` — split from the async `send_to_viewer` so the handover is testable without an event loop.

  - **Chain, one-way:** `molecularViewer → cubeTab → {cubeRender → volumeData, volumeData → {molecularSurface, (volumeNumba), cubeFile, help}}`.   - **Two cube readers, deliberately.** `cubeFile.read_cube`/`write_cube`/`format_cube` stay the strict, unchanged ones the Fukui tool uses. `read_cube_volumes` → `List[CubeVolume]` (lengths bohr, `axes` row k = step of index k, point (i,j,k) at `origin + (i,j,k) @ axes`) reads any cube: negative atom count = orbital cube (the NMO line may wrap; values are MO-fastest; **one volume per orbital**), negative voxel count = Å (converted), skewed and unequal axes, Fortran exponents without `E` (`1.234-100`) repaired by regex. Packing engines are bit-identical to the original loop (`fill_solvent_box_legacy`), which draws `random.random()` for the solvent type, then the rotation, then `random.uniform` ×3; bounding radii here exclude vdW, the target is `round()`ed (single uses `floor`), and a molecule too large for the box ends the loop rather than raising — all preserved. Molecule kinds `solvent_A`/`solvent_B` drive the canvas colours. Tests: [tests/test_mixtureSolventBox.py](tests/test_mixtureSolventBox.py).
- **[sharedWallBox.py](sharedWallBox.py)** — two z-stacked regions. `build_box` packs Box 1 then Box 2; Box 2 is checked against Box 1's entries (solute included) through a second `MoleculeGrid` (`fill_box_fast`), bit-identical to the original `fill_box_async` (kept as `fill_box_legacy`). The never-called `fill_box_sync`/`build_shared_wall_box_sync`, the dict-based entry grid and the publish/apply progress plumbing were removed as dead code. `molecule_regions` records each molecule's region; pre-optimization adds a `SlabRestraint` (flat-bottom on each molecule's COM z, `preopt_slab_bounds`) so the interface survives, and non-periodic walls are per-atom (`preopt_wall_bounds`: x/y at each box's padding, z only on the outer faces). The packed `shared_wall_box.xyz` keeps the original shift to min z = 0; `*_preopt.xyz` is in cell coordinates. Tests: [tests/test_sharedWallBox.py](tests/test_sharedWallBox.py).
- **[single_solute_solvent_box.py](single_solute_solvent_box.py) + [solventPacking.py](solventPacking.py) / [solventPackingNumba.py](solventPackingNumba.py) / [periodicPreOptimizer.py](periodicPreOptimizer.py) / [systemProperties.py](systemProperties.py) / [boxConstructionView.py](boxConstructionView.py)** — random-insertion solvation box with optional periodic pre-optimization, system properties and a live construction canvas. Spec: [docs/superpowers/specs/2026-10-15-solvation-box-preopt-design.md](docs/superpowers/specs/2026-10-15-solvation-box-preopt-design.md). Only the `*UI` class and `ConstructionView` touch Toga (Toga is imported lazily inside the latter); the rest are tested headless, each with a `toga`-not-in-`sys.modules` subprocess test.
  - **Packing engines give bit-identical boxes.** `fill_solvent_box_legacy` is the original pure-Python loop, kept as the reference; `fill_solvent_box_fast(engine)` reaches the *same* accept/reject decision per attempt via `MoleculeGrid` (cell list, cells ≥ the legacy centre-filter distance `2R + 2.5`) and `atoms_clash` (numpy, or the numba kernel). Identity depends on reproducing the float64 operations exactly: `dx - L*np.round(dx/L)` (both `round`s are half-to-even), `dist2 = dx*dx + dy*dy + dz*dz` written in that order, `cutoff = scale*(ri+rj)`, and the legacy centre filter applied unchanged to the cell-list candidates. `RotationStream` draws `Rotation.random(512)` blocks — identical to sequential `Rotation.random()` calls, and `x @ R.T` equals `Rotation.apply` bit for bit (tested). Tests in [tests/test_single_solute_solvent_box.py](tests/test_single_solute_solvent_box.py) compare whole boxes with `np.array_equal`; **any change to the decision arithmetic must keep them passing.** `solventPackingNumba.py` is the only numba importer besides `espNumba.py`.
  - **The logic class no longer reads widgets in the engine**: `read_params` (returns `bool`) copies switches into `rotate_solvent`/`include_solute`/`preoptimize`/… so `build_box(progress)` and `run_preoptimization(progress)` run in `asyncio.to_thread`; progress dicts (`stage` = `insertion`/`preopt`, with a `molecules` list for the canvas) are throttled to `PROGRESS_REPORT_INTERVAL` and marshalled with `loop.call_soon_threadsafe(self._apply_progress, …)`. `self.molecules` = `(kind, elements, coords)` per placed molecule in `self.data` order — the pre-optimizer's source of connectivity (never guessed across a periodic boundary).
  - **Pre-optimization** ([periodicPreOptimizer.py](periodicPreOptimizer.py)): Packmol-style penalty `K(d²−σ²)²` for intermolecular pairs with `d < σ = vdw_scale(r_i+r_j)` (+ solute clearance for solute–solvent pairs) — the builder's own criterion, so `E = 0` ⇔ no clash. Finite range → exact PBC via `cKDTree(boxsize=L)` + minimum image; requires `σ_max < min(L)/2` (otherwise `ValueError`, which the builder records in `preopt_error` and still writes the packed box). Non-periodic → harmonic walls at the padding. `RigidBodyModel` = centroid + rotation vector per molecule with the SO(3) left-Jacobian gradient (`dE/dw = J_lᵀ τ`); `FlexibleModel` tiles `molecularPreOptimizer.ForceField.from_geometry` (references from the *input* geometry, no torsions) with `ForceField.combine`. Both gradients are pinned by finite-difference tests. `wrap_molecules` shifts whole molecules by cell vectors so COMs are in `[0, L)`. The scipy callback argument **must** be named `intermediate_result` to receive `.fun`; raising `StopIteration` there is how Cancel works. `ForceField` now caches its term arrays in `__init__` (same numbers, much faster for tiled boxes).
  - **System properties** ([systemProperties.py](systemProperties.py)): `N_e = ΣZ − Q`, `Q = q_solute + N_solvent·q_solvent`; multiplicity is **required and never inferred**, validated after the build (`(N_e + M)` odd, `M ≤ N_e + 1`); an inconsistent value is reported, not replaced, and **Update properties** re-validates without rebuilding.
  - **Outputs** keep their old names/format; additions are `*_preopt.xyz` (cell on the comment line) and the properties/pre-opt blocks in the summary `.txt`. The UI is three tabs (Setup / Construction / Summary) over a fixed run bar with **Cancel** (no files written for a cancelled run). `benchmarks/bench_solvent_box.py` times legacy vs numpy vs numba and checks identical output.
  - **The pre-optimization target is its own scale** (`preopt_contact_scale`, default `max(0.90, vdw_scale)` via `effective_preopt_contact_scale()`): packing already guarantees `d >= vdw_scale*(ri+rj)`, so relaxing to the *packing* scale is a guaranteed no-op (a live run reported "no overlaps to relax"). The minimizer aims at `sigma*(1 + OPTIMIZATION_MARGIN)` (1 %) while reports use the true sigma, so contacts settle just outside the cutoff instead of L-BFGS stopping a hair inside it.
  - **The construction view is a bitmap, not a `toga.Canvas`** ([boxConstructionView.py](boxConstructionView.py)): on WinForms a Toga canvas replays every drawn shape through pythonnet on each repaint (~120 ms idle for 2300 atoms, *seconds* while the packing thread competes for the GIL — a live test froze the window for 9 s). `render_image` draws with Pillow (2x supersampled), and `ConstructionView._set_native_bitmap` copies the pixels straight into a locked `System.Drawing.Bitmap` with `ctypes.memmove` — because `toga.Image(pil)` itself costs ~170 ms (PNG + element-wise byte[] conversion). Falls back to Toga's `image` setter on any failure. Repaints are throttled to `max(min_interval, PAINT_BUDGET_FACTOR * last paint time)`. Rotation is by buttons (ImageView has no mouse events). Measured in the live window: UI loop lag ≤ 80 ms during a 30 Å build. The numba kernels are `nogil=True` so the worker releases the GIL inside them.

## Adding a new tool

1. Create a self-contained `myTool.py` exposing a `MyToolUI` class following the `layout_main_window` / `workflow` pattern above, reusing the `FramesCounter`/`DisplayPlots` mixins where relevant.
2. Import it in [gqteaWinToga.py](gqteaWinToga.py) and add `("Button label", MyToolUI)` to the appropriate tab list.
3. Add help text to `HelpGqteaWin` in [help.py](help.py) and, if user-facing, document it in [USER_MANUAL.md](USER_MANUAL.md).
