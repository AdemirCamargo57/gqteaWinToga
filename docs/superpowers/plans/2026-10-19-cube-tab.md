# Cube Tab (3D Molecular Viewer) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a **Cube** tab to the 3D Molecular Viewer that loads several Gaussian cube files, draws ± isosurfaces and a slice plane, combines compatible grids, and exports cubes and images.

**Architecture:** Format I/O is added to `cubeFile.py` (existing functions untouched). The numeric work lives in a Toga/GL-free `volumeData.py`, with an optional numba cell-scan kernel in `volumeNumba.py`. Drawing is a GL-only `cubeRender.CubeSceneLayer`, and the Toga tab is a headless-testable `cubeTab.CubeTabController`. `molecularViewer.py` gets only the integration points: one tab entry, hook overrides in `MolecularViewerUI`, and a `show_structure` flag.

**Tech Stack:** Python 3.13, numpy 2.4.2, scipy 1.17, numba 0.68 (optional), PyOpenGL, toga-winforms 0.5, pytest.

**Spec:** [docs/superpowers/specs/2026-10-19-cube-tab-design.md](../specs/2026-10-19-cube-tab-design.md)

## Global Constraints

- Baseline: 4 pre-existing failures (`test_meanResidenceTime.py::TestAdvancedOptionsExposed::test_every_run_parameter_is_supplied_by_the_ui` + three table-styling tests in `test_plotter.py`). They are not regressions.
- Existing behaviour is preserved:
  - `CubeData`, `read_cube`, `write_cube` and `format_cube` stay byte-for-byte unchanged;
  - `marching_tetrahedra` returns identical meshes (the ESP/Fukui/surface tests must pass unchanged);
  - the base-class hooks `render_scene_extras`/`draw_screen_overlay` stay empty;
  - the five existing tabs keep their order.
- Numba is optional: `volumeNumba.py` is the only new importer of numba. Every caller falls back to numpy with the same vertices.
- These modules must never import Toga, each enforced by a subprocess test: `cubeFile.py`, `volumeData.py`, `volumeNumba.py`, `cubeRender.py`. `cubeRender.py` must also never import GLFW.
- Lengths are bohr inside `cubeFile`/`volumeData`; Å only at the render/structure/export boundary. `BOHR_RADIUS_ANGSTROM = 0.529177210544`.
- Value parsing: `np.array(text.split(), dtype=np.float64)`. **Not** `np.fromstring`: measured 14 s vs 1.2 s for 8 M values.
- UI errors go through `toga.ErrorDialog`/status lines; nothing raises out of an async handler.

### Task 1: General cube reader/writer (`cubeFile.py`)

**Files:** Modify `cubeFile.py` (append only). Test `tests/test_cubeFile.py`.

**Interfaces — produces:**
- `@dataclass CubeVolume(title: str, comment: str, atomic_numbers: np.ndarray, nuclear_charges: np.ndarray, coordinates: np.ndarray, origin: np.ndarray, axes: np.ndarray, values: np.ndarray, orbital: Optional[int] = None)`, all lengths in bohr, `axes` row k = step of index k.
- `read_cube_volumes(path) -> List[CubeVolume]`: one entry per orbital.
- `write_cube_volume(path, volume) -> str`.
- `BOHR_RADIUS_ANGSTROM = 0.529177210544`.

- [ ] Step 1: Write failing tests:
  - plain cube equals `read_cube` values;
  - orbital cube with 1 MO and with 3 MOs (MO header line; values MO-fastest) splits into 3 volumes with `orbital` = 5, 6, 7;
  - an MO list wrapping over two lines (12 MOs, 10 per line);
  - negative voxel counts → Å converted to bohr (origin, axes, atoms);
  - skewed axes kept as given;
  - unequal spacing kept;
  - `1.234-100` repaired;
  - truncated data → `ValueError` "truncated";
  - singular axes → `ValueError`;
  - round trip `write_cube_volume → read_cube_volumes` within the `%13.5E` precision (relative 1e-5);
  - writing an orbital volume gives a positive atom count;
  - the bohr constant equals `coordinateConverter.BOHR_RADIUS_ANGSTROM`.
- [ ] Step 2: Run `python -m pytest tests/test_cubeFile.py -q`. Expect failures (names undefined).
- [ ] Step 3: Implement the reader:
  - header lines 0-5; `natoms<0` → orbital;
  - voxel count `<0` → Å factor `1/BOHR_RADIUS_ANGSTROM` for origin/axes/atoms;
  - atoms on the next `|natoms|` lines;
  - for an orbital cube, read integer tokens from the following lines until `1 + NMO` integers are collected;
  - the rest of the text is joined and parsed with `split` (regex `(?<=[0-9])([+-][0-9]{2,3})(?=\s|$)` → `E\1` on failure);
  - reshape `(nx, ny, nz, nmo)`;
  - writer layout identical to `format_cube` but with full axes.

### Task 2: Split `marching_tetrahedra` + numba kernel + `volumeData` isosurface

- `volumeNumba.tetra_cut_edges(values, isovalue) -> same pair` (empty arrays when nothing is cut).
- `volumeData.numba_available() -> bool`.

- [ ] Step 1: Failing tests:

  - a sheared grid (`axes=[[h,0,0],[h/2,h,0],[0,0,h]]`) of the same blob → same radius check;
  - `axes` with negative determinant: normals point outward (dot with radial > 0 for > 99 % of vertices);
  - iso above max → `None`;
  - numba vs numpy: identical vertices, identical sorted triangles (skip without numba);
  - `use_numba=True` with `volumeData.volumeNumba = None` → `ValueError`;
  - Toga-free subprocess for `volumeData` and `volumeNumba`.
- [ ] Step 2: Run; expect failures.
- [ ] Step 3: Move the cell-scan half of `marching_tetrahedra` verbatim into `tetra_cut_edges` and the finishing half verbatim into `mesh_from_cut_edges`; `marching_tetrahedra` calls both.
- [ ] Step 4: Write the numba kernel: two-pass prange over x-slabs, the same tetra table, the same polygon order and the same edge id `((x*ny+y)*nz+z)*7 + k` using `_EDGE_LUT`. In `volumeData.isosurface`, call the cell scan on `sign*values` with origin 0, spacing 1, `density=None`; map `origin + idx @ axes`; flip triangles if `det<0`; compute area-weighted normals.
