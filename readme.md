# gqteaWinToga

gqteaWinToga is a desktop molecular analysis toolkit developed by the gQTEA group
for preparing, inspecting, converting, and analyzing molecular dynamics and
electronic-structure simulation data. The application provides a graphical
interface built with [Toga](https://toga.readthedocs.io/) and collects several
specialized tools for CPMD, Quantum ESPRESSO `cp.x`, ORCA, surface hopping, and
trajectory analysis workflows.

The current application title identifies the toolkit as **gQTEA-1.6.0 Molecular
Analysis Toolkit**.

## Capabilities

The main window organizes the tools into five tabs.

### Geometry

- Bond length analysis
- Bond angle analysis
- Dihedral angle analysis
- Hydrogen bond analysis

These modules work with molecular trajectory files, commonly `TRAJEC.xyz`, and
can calculate averages, distributions, and free-energy profiles from probability
distributions.

### Inputs

- CPMD input generation
- Surface hopping input builder
- Molecular collision setup
- Quantum ESPRESSO `cp.x` input builder
- ORCA input builder
- gqteaMD input builder
- Gaussian Fukui input builder (one Gaussian 16 linked job: optimization of N, then `Geom=Check` single points on N+1 and N-1; plus a formchk script)

### Structural Analysis

- Radial distribution function
- Mean residence time
- Legacy mean residence time workflow
- Velocity autocorrelation function
- Single-solute solvent box builder
- Mixed-solvent box builder

### Thermodynamics

- Classical rate constant calculation

### General Tools

- 3D molecular viewer
- Electrostatic surface potential (ESP) mapped on electron-density isosurfaces from Gaussian `.fchk`/`.fch`, with Multiwfn-style surface extrema
- Fukui functions f+, f-, f0 and the dual descriptor from Gaussian N/N+1/N-1 .fchk files, with surface extrema, cube export and built-in Hirshfeld condensed indices (no external program)
- Molecular orbitals (Orbitals tab of the 3D molecular viewer) of Gaussian `.fchk`/`.fch` SCF wavefunctions (restricted, unrestricted, restricted open-shell), as GaussView shows them: MO table with labels, occupancies and energies, red/green phase isosurfaces or |phi|^2 on Coarse/Medium/Fine grids, Solid/Transparent/Mesh styles, MO energy-level diagram, cube and energy-table export; validated against cubegen (no external program at run time)
- QTAIM topology analysis (QTAIM tab of the 3D molecular viewer) of the electron density from Gaussian `.fchk`/`.fch`: critical points (3,-3), (3,-1), (3,+1), (3,+3) with rho, Laplacian, Hessian eigenvalues, ellipticity and energy densities G, K, V, H; bond and ring paths; Poincare-Hopf check; text report; 3D view and Multiwfn-style 2D plane map, both exportable as images. Algorithms and defaults follow Multiwfn and are validated against Multiwfn 2026.7.15 (no external program at run time)
- Natural transition orbitals (NTO tab of the 3D molecular viewer) of CIS/TDA/TD excited states from a Gaussian `.fchk`/`.fch` and the job's output (restricted and unrestricted): pair weights, hole and particle isosurfaces, cube files, an NTO `.fchk`, a text report and a GaussView-style UV-Vis spectrum of all states (f sticks and broadened ε, saved as JSON); Multiwfn's definition, validated against Multiwfn 2026.7.15 (no external program at run time)
- CPMD energy plotting
- Vanderbilt USPP generator (runs the bundled `runatom` to make ultrasoft pseudopotentials, with transferability tests and a formatted file for CPMD)
- Molecular axis alignment
- Frame selection
- Frame selection by interatomic distance range
- CPMD input to XYZ conversion
- Surface hopping geometry analyzer
- `*.pos` to `trajec.xyz` conversion
- Force conversion from Quantum ESPRESSO `cp.x` `*.for` files
- Coordinate conversion (file formats, and Angstrom ↔ Bohr)
- Unit conversion

## Repository Layout

This repository is currently organized as a flat Python source tree. The main
launcher is:

```text
gqteaWinToga.py
```

Each major tool is implemented in its own module, for example:

- `bond.py`, `bondAngle.py`, `dihedralAngle.py`, and `hbond.py` for geometry
  analysis
- `cpmdInput.py`, `cpx_input_builder.py`, `orca_input_builder.py`, and
  `gqteaMDinptBuilder.py` for input generation
- `molecularViewer.py` for OpenGL-based molecule visualization
- `electrostaticSurfacePotential.py`, `gaussianWavefunction.py`, `espIntegrals.py`, `molecularSurface.py`, `espViewer.py` (and the optional `espNumba.py`) for the ESP surface tool
- `fukuiFunctionAnalyze.py`, `hirshfeldCharges.py`, `proatomDensities.py` (free-atom densities, generated by `tools/make_proatom_densities.py`) and `cubeFile.py` for the Fukui function tool
- `qtaimTopology.py`, `qtaimAnalysis.py`, `qtaimLayer.py` and `qtaimTab.py` for the QTAIM tab (density derivatives in `gaussianWavefunction.py` and the optional `densityNumba.py`)
- `molecularOrbitals.py` and `orbitalTab.py` for the Orbitals tab
- `excitationData.py`, `ntoAnalysis.py`, `uvVisSpectrum.py` and `ntoTab.py` for the NTO tab (MO coefficients and orbital values in `gaussianWavefunction.py`)
- `fukuiInput.py` and `fukuiInputBuilder.py` for the Gaussian Fukui input builder; `gaussianUtilities.py` locates Gaussian utilities such as cubegen
- `plotter.py` and `displayPlots.py` for plotting
- `help.py` for application help text and shared atomic data

## Requirements

- Python 3.10 or newer is recommended.
- Windows is the primary target when using the Toga WinForms backend.
- A working graphical desktop session is required.

Python package dependencies used by the application include:

- `toga-winforms`
- `numpy`
- `scipy`
- `matplotlib`
- `glfw`
- `PyOpenGL`
- `PyOpenGL-accelerate`
- `PyMuPDF`
- `numba` (installed by default, optional at run time: about 5x faster ESP in the ESP surface tool; about 4x faster electron densities in the ESP and Fukui tools; 4-46x faster QTAIM analysis and 2D maps; 20-50x faster solvent-box packing)

The code also uses Python standard-library modules such as `asyncio`, `csv`,
`dataclasses`, `decimal`, `html`, `http.server`, `math`, `os`, `pathlib`,
`random`, `re`, `statistics`, `subprocess`, `tempfile`, `threading`, and
`typing`.

## Installation

Clone the repository and create a virtual environment:

```powershell
git clone https://github.com/AdemirCamargo57/gqteaWinToga.git
cd gqteaWinToga
python -m venv venv
.\venv\Scripts\Activate.ps1
```

Install the runtime dependencies:

```powershell
python -m pip install --upgrade pip
python -m pip install toga-winforms numpy scipy matplotlib glfw PyOpenGL PyOpenGL-accelerate PyMuPDF
```

If you are already working inside this repository's `venv/src` directory, run the
install command from the active virtual environment.

## Running the Application

From the source directory, start the GUI with:

```powershell
python gqteaWinToga.py
```

The application opens a desktop window titled:

```text
gQTEA - grupo de Quimica Teorica e Estrutural de Anapolis
```

Select a tab, choose the desired tool, fill in the required file paths and
parameters, and run the calculation or conversion from the tool window.

## Usage Examples

### Analyze a Bond Length Distribution

1. Start the application with `python gqteaWinToga.py`.
2. Open **Geometry**.
3. Select **Bond length analysis**.
4. Load a CPMD `TRAJEC.xyz` trajectory file.
5. Enter the two atom indices, simulation temperature, and histogram bin count.
6. Run the analysis to generate bond-length statistics, distributions, and
   free-energy data.

### Plot CPMD Energy Data

1. Open **Tools**.
2. Select **Energy plots**.
3. Browse to a CPMD energy file.
4. Enter the simulation time step.
5. Select one or more plot types, such as temperature, Kohn-Sham energy, total
   energy, or CPU time.
6. Generate the plots.

### Build a CPMD Input

1. Open **Inputs**.
2. Select **CPMD Inputs**.
3. Provide a prefix, total charge, periodic box parameters, energy cutoff, dual
   for rho expansion, cell symmetry, and an XYZ starting geometry.
4. Generate the CPMD input files for wave-function optimization, equilibration,
   or production simulation workflows.

### Extract Surface Hopping Frames by Electronic State

1. Open **Tools**.
2. Select **SH Geometry Analyzer**.
3. Enter the number of electronic states.
4. Select a root directory containing simulation subfolders with `SH_STATE.dat`
   and `TRAJEC.xyz`.
5. Run the extractor to create state-separated `stateX.xyz` trajectory files and
   the summary file `sh_avg_perc.dat`.

## Supported Input and Output Files

Common files used by the toolkit include:

- `.xyz` molecular geometry and trajectory files
- Gaussian formatted checkpoint files (`.fchk`, `.fch`) and the ESP extrema file `<name>_ESP_extrema.txt`
- Gaussian cube files written by the Fukui tool
- Orbitals tab outputs `<name>_MO<n>[_alpha|_beta][_density].cube`, `<name>_MO_energies.txt` and the energy-level diagram `<name>_MO_levels.json` (reopened by the plotter's JSON plot type)
- QTAIM report `<name>_QTAIM.txt` and 2D-map data `<name>_QTAIM_map.json` (reopened by the plotter's JSON plot type)
- Gaussian CIS/TDA/TD output files (`.log`, `.out`) read by the NTO tab, and its outputs `<name>_state<n>_NTO.txt`, `<name>_state<n>_NTO<k>_hole.cube` / `_particle.cube`, `<name>_state<n>_NTO.fchk` and the spectrum `<name>_UVVis.json` (reopened by the plotter's JSON plot type)
- `TRAJEC.xyz` CPMD trajectory files
- CPMD `GEOMETRY.xyz` files
- CPMD energy files
- Surface hopping `SH_STATE.dat` files
- Quantum ESPRESSO `cp.x` input and force files
- ORCA input files
- Vanderbilt USPP generator (runs `runatom`)

Generated outputs depend on the selected tool and may include analysis tables,
selected trajectory frames, converted geometry files, generated input decks, and
plots.

## Packaging for Windows

The project can be packaged as a Windows executable with
[`auto-py-to-exe`](https://pypi.org/project/auto-py-to-exe/) and installed with
Inno Setup.

Basic packaging workflow:

```powershell
cd <project-venv>
python -m pip install auto-py-to-exe
auto-py-to-exe
```

When packaging the application, ensure the required runtime packages are included:

- `toga-winforms`
- `matplotlib`
- `numpy`
- `scipy`
- `glfw`
- `PyOpenGL`
- `PyOpenGL-accelerate`
- `PyMuPDF`

`auto-py-to-exe` may not automatically find the GLFW DLL. If packaging fails or
the molecular viewer cannot start, manually include the DLL from a path similar
to:

```text
venv\Lib\site-packages\glfw\glfw3.dll
```

### Interactive plots in the packaged build

The analysis tools show their figures through an interactive matplotlib window
(zoom/pan/save toolbar). In the packaged `.exe` this window is produced by the
application re-launching itself with a `--plot-viewer` flag, which needs an
interactive matplotlib backend to be bundled. Ensure the build includes:

- `tkinter` (the `TkAgg` backend used by the viewer; add it as a hidden import
  if `auto-py-to-exe` does not pick it up automatically)

If `tkinter`/`TkAgg` is missing from the bundle, the plot window will fail to
open in the packaged build even though it works when running from source.

### Tool modules in the packaged build

The main window imports the tools by name when they are needed (see
`toolLoader.py`), which PyInstaller cannot see on its own. `toolLoader.py`
therefore lists every tool module as a literal `import` in
`_frozen_build_imports()`, a function that is never called, so the build
bundles them without extra hidden imports. If a packaged build reports
"Tool could not be loaded" with `No module named ...`, add that module as a
hidden import.

### runatom (Vanderbilt USPP generator) in the packaged build

The Vanderbilt USPP Generator runs two programs that **must ship with
gqteaWinToga**:
- `runatom.exe`, a statically linked build of USPP 7.3.6;
- `reform.exe`, USPP's converter, which writes the formatted file CPMD reads
  with the `&ATOMS` line `*<file> FORMATTED`.

Both are committed in `third_party/uspp-736/bin/`. Rebuild them with
`third_party/uspp-736/build_runatom.ps1`, which needs MSYS2 UCRT64 gfortran.
In auto-py-to-exe, under *Additional Files*, add:

- `third_party/uspp-736/bin/runatom.exe` with destination `uspp/`
- `third_party/uspp-736/bin/reform.exe` with destination `uspp/`
- `third_party/uspp-736/Work` with destination `uspp/Work` (the input library)
- `third_party/uspp-736/Source` with destination `uspp/Source`
- `third_party/uspp-736/Utils` with destination `uspp/Utils`
- `third_party/uspp-736/patches` with destination `uspp/patches`
- `third_party/uspp-736/Doc` with destination `uspp/Doc` (the manual points
  users to `Doc/INPUT_AE`, `Doc/INPUT_GEN` and `Doc/TUTORIAL`)
- the files `third_party/uspp-736/AA-README`, `third_party/uspp-736/Source/LICENSE`
  and `third_party/uspp-736/PROVENANCE.md` with destination `uspp/`

GPL v2 requires shipping the source with the programs, so keep the folders
under their own names (a flat `uspp/` would merge their README, Makefile and
LICENSE files).

**Import library case...** opens its folder dialog in the input library
(`Work`). The library is found relative to the installed application, never
the current working directory. It may be in any of these places, checked in
this order:
1. `<install folder>/third_party/uspp-736/Work`, next to `gqteaWinToga.exe`;
2. `<bundle>/third_party/uspp-736/Work` (the `_internal` folder of a
   PyInstaller 6 onedir build);
3. `<bundle>/uspp/Work`, the destination listed above.

If none of them exists, the dialog opens in the Windows default folder.

At run time each program is looked for in this order:
1. the path typed in the window (`reform.exe` next to it);
2. `%GQTEA_RUNATOM%` / `%GQTEA_REFORM%`;
3. `<bundle>/uspp/`;
4. the repository copy;
5. `PATH`.

Windows SmartScreen or antivirus software may question the unsigned programs;
they are not packed or obfuscated.

## Development Notes

- The application is launched from `gqteaWinToga.py`.
- Most user-facing modules expose a `*UI` class that a menu button opens.
- Keep new tools self-contained in their own module when possible, then add a
  `ToolSpec(label, module, class)` to the appropriate tab in
  `toolLoader.TOOL_TABS` and the module to `_frozen_build_imports()` there.
  Do not import tools in `gqteaWinToga.py`: the main window would wait for them.
- Prefer adding clear help text in `help.py` for new analysis workflows.
